# Attestara: completion endpoint

Current: LOCAL_USABLE for the verified single-operator Linux x86_64
`local-cli-snapshots` profile. Published OSS v1 remains a separate C40 gate.

## C30: locally usable

All C01-C30 acceptance and negative cases have actual source-bound evidence. A clean supported host completes git clone, npm run setup, npm start, the entire REFERENCE_WORKFLOW.md task, restart and restore using the actual engine/store/providers. A generic JSON preview, mocked authority or web-only /readyz is insufficient. Record real limits and resources; no paid account, public domain or sibling clone.

## C39/C40: complete OSS v1

C39 verifies actual C01-C38 proof, full source/engine packaging, dependency/fixture licenses, security/recovery, UX, upgrade and independent onboarding. npm run release:check fails on missing or unverified work. C40 then publishes through the maintainer-authorized source/tag/artifact workflow, installs the actual published version and repeats the complete reference task. Only then may complete v1 be verified.

`npm run release:check` runs the full checks again on a clean committed source
snapshot; a previous green report cannot satisfy a new run. See
[the release gate](../engineering/RELEASE_GATE.md) for prerequisites, exact evidence
boundaries, exit codes and retained reports. C39 certification also requires the
actual candidate's GitHub Actions results; local success is identified separately.

Planning files, forty commits, green shell CI or a web-only package are not completion evidence. Customer pilots, marketing domains, billing and app stores are not local OSS requirements. Untrusted public execution, multi-tenant SaaS and unbounded resources are outside this v1 profile. Protected-file restrictions remain in force.
